# Management MCP server

Status: **implemented** (`internal/mcp`). This document describes what exists and
the decisions made from the initial survey.

## Requirements

- **Off by default.** Without `-mcp-addr`, no MCP code listens on a port.
- **Its own port**, separate from `-listen`, `-amqp-addr` and `-http-addr`.
- **No login.** Whoever reaches the port manages the emulator. For that reason
  the recommended default is a loopback address; binding outside loopback logs a warning.
- Native in the single binary, with no new dependency (the protocol is JSON-RPC and was
  written by hand, ~600 lines).

## Flags

| Flag | Default | Purpose |
|---|---|---|
| `-mcp-addr` | empty (off) | MCP address, e.g. `127.0.0.1:5680`. The endpoint is `/mcp`. |
| `-mcp-readonly` | `false` | Registers only the tools that read. |
| `-mcp-allow-data` | `false` | Also registers the tools that read, send or delete messages. |

At startup, all three can also come from the environment: `OSB_MCP_ADDR`,
`OSB_MCP_READONLY` and `OSB_MCP_ALLOW_DATA` (`true`/`false`); the flag wins over the
variable, and an invalid boolean prevents startup. With neither of the two, MCP
stays off.

`-mcp-token` from the survey was dropped: the requirement is MCP without login.

## Transport

Streamable HTTP, `POST /mcp`, one JSON response per request (notification: 202
with no body; JSON-RPC batch accepted). `GET` and `DELETE` return 405: the server
never opens its own stream. No `Mcp-Session-Id` (no per-session state).
Protocol versions: 2025-06-18, 2025-03-26 and 2024-11-05 (negotiates the client's
when it knows it, otherwise returns the newest).

An `Origin` that is not loopback (`localhost`, `*.localhost`, loopback IP)
gets 403. Browsers always send `Origin` on a POST, so this blocks
pages from other sites and DNS rebinding (an attacker's name that resolves to
this machine sends identical `Origin` and `Host`, which is why `Host` does not count);
programs do not send `Origin` and get through.

## Architecture

- `internal/mcp` depends on `server`, `broker`, `config` and `terraform` (and not the
  other way around, because `config` already imports `server`). `main` only creates and wires
  the endpoint to the `*server.Server`.
- Every tool operates through `broker.Broker` and `server.Server`, like the portal,
  with `Actor = "mcp"` in the activity log. It goes through neither ATOM nor AMQP.
- Each tool's input schema is generated by reflection over the input struct
  (`json`, `desc`, `enum`, `required`), so the code and the schema do not diverge.
- `internal/message` (new) centralizes building and reading AMQP messages
  (`Spec.Build`, `Body`, `Resend`, `Jsonable`, `TypeName`) and is used by MCP and
  the portal.
- `server.Namespace` gained `Apply` (applies declared entities, with `prune` and
  `dryRun`), `Reset`, `DBPath`; `server.Server` gained `Version`, `Started`,
  `ConnectionStringFor` (`internal/server/manage.go`).

## Tools

Legend: **R** reads metadata, **W** writes metadata, **D** requires
`-mcp-allow-data`, **!** deletes data and requires `confirm: true`. All accept
`namespace` (default: the default namespace). Durations are ISO 8601 (`PT30S`) or
a number of seconds.

Entities: `list_entities` R, `get_entity` R, `create_queue` W, `create_topic`
W, `create_subscription` W, `update_entity` W, `delete_entity` W!. Properties
use the JSON names of `broker.Properties` and nothing is limited to the
ranges of the official emulator.

Rules: `list_rules` R, `get_rule` R, `add_rule` W, `update_rule` W,
`delete_rule` W, `set_rules` W, `test_rule` R (evaluates filter and action against a
sample message, without sending anything).

Observability: `get_namespace_info`, `get_metrics`, `get_metric_totals`,
`query_activity_log`, `get_overview` (DLQ, deferred, scheduled, largest queues,
disabled entities), `get_server_status`, `get_certificate`, `list_namespaces`.
All R.

Messages (D): `peek_messages` (active, DLQ or transfer DLQ; body
truncated at `max_body_bytes`, UTF-8 text or base64), `send_message` (with
`count`), `send_batch`, `purge_entity` !, `requeue_dead_letters` !,
`cancel_scheduled`, `list_sessions`, `get_session_state`, `set_session_state`.
Receiving with a lock (`Receive`/`Complete`/`Abandon`) was left out: the lock is
connection state; `peek` covers inspection. Setting session state locks the session for a
moment (the broker only hands it to the lock owner), so it fails while a
client holds it.

Configuration and state: `export_config` R, `diff_config` R, `apply_config` W (!
with `prune`), `reset_namespace` W!, `list_locks` R, `set_lock` W, `delete_lock`
W, `set_tags` W, `set_log_level` W (only if `main` passes the
`LevelVar`, which the binary does).

- `diff_config` and `apply_config` accept Config.json (`format: config_json`) or
  Terraform (`format: terraform`, with `content` or `files`, `variables`,
  `module_map` and `drop_default_rule`, like the flags). They create what is missing and
  update what differs, including rules; they delete nothing without `prune`.
  Tags, locks and policies in the content are not applied. Content with several
  namespaces applies the one named like the target; if none matches, it fails (this prevents a
  `prune` from emptying the namespace).
- `reset_namespace` deletes all entities and messages and redeclares what the
  server started up declaring (`restore_initial_config`, default `true`). Metrics and
  activity log remain. Entity-scoped policies that the server started up
  declaring come back with the same keys (deleting the entity deletes the policy).
- Terraform received through MCP runs in `Sandbox` mode (`terraform.Options`):
  local modules can only be inside the submitted content (a `source = "../.."`
  is refused) and the emulator's `TF_VAR_` environment variables are ignored.

Namespace security: `list_authorization_rules` R, `create_sas_policy` W,
`delete_sas_policy` W, `generate_sas_token` R, `issue_dev_token` R (only with
`-auth full -dev-issuer`). Policy keys appear in the result.

Geo: `geo_dr_status`, `geo_dr_pair`, `geo_dr_failover`, `geo_dr_break`,
`geo_dr_delete_alias`, `geo_replication_status`, `geo_replication_enable`,
`geo_replication_disable`, `geo_replication_promote`.

## Resources and prompts

Resources: `osb://namespaces`, `osb://certificate.pem`, `osb://export/config.json`,
`osb://export/main.tf` and, per namespace, `osb://{ns}/info`, `/entities`,
`/activity`. Templates: `osb://{ns}/queues/{name}`, `/topics/{name}`,
`/topics/{topic}/subscriptions/{name}`. Each resource is served by the equivalent
read tool, so the two do not diverge.

Prompts: `diagnose_dead_letters`, `explain_routing`, `prepare_integration_test`.

## Security

- Off and loopback by default; no login by project decision.
- `-mcp-readonly` removes the writes; the message tools exist only with
  `-mcp-allow-data`.
- Tools that delete data (`delete_entity`, `purge_entity`,
  `requeue_dead_letters`, `reset_namespace`, `apply_config` with `prune`) require
  `confirm: true` in addition to the `destructiveHint` (for `apply_config` only with `prune`).
- The namespace's `ReadOnly` and `CanNotDelete` locks apply to MCP just as to the portal.
- Message bodies and the activity log come back accompanied by a warning that they are
  data written by third parties (prompt injection); bodies are truncated.
- Limits: requests up to 16 MB, `peek` up to 100 messages per call,
  `send_batch` and `count` up to 1000, 2 minutes per call.

## Tests

- `test/integration/mcp_test.go` (Go SDK as the effect verifier, minimal MCP
  client): protocol, tool gating, entities (checked through
  `admin.Client`), rules (real routing through the SDK), messages (send, peek,
  purge, DLQ and requeue, scheduled, sessions, truncation), config (diff, apply,
  prune, Terraform, reset, export), namespaces, locks, policies and tokens,
  observability, resources and prompts, Geo, and the binary (`TestBinaryMCP`:
  off by default, its own port, flags).
- `test/node/mcp.test.mjs`, via `TestNodeMCP`: official
  `@modelcontextprotocol/sdk` client, with effects checked through `@azure/service-bus`.
  Requires `npm ci` in `test/node`; without `node_modules`, it is skipped.
- Unit: `internal/mcp` (properties, schema, `Duration`, `Origin`) and
  `internal/message`.

## Out of scope (for now)

- Receiving with a lock; server-to-client notifications (`listChanged`,
  `subscribe`); authentication.
- The containerized e2e does not start MCP.
